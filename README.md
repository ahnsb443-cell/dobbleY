# DOUBLE Y · 언주역점 페이롤 — Firebase 버전

회원 등록·추가 결제 → 수업 기록·휴대폰 서명 → 페이롤 자동 계산 →
월말 직원 제출·관리자 다짐 대조·승인·마감을 지원합니다.

**현재 권장 운영 경로는 Firebase Authentication + Firestore + Cloud Functions + Hosting입니다.**
Firebase 연결 코드를 구현했으며 실제 프로젝트 생성·외부 배포·GitHub push는 실행하지 않았습니다.
실제 회원 데이터나 공용 관리자 비밀번호는 포함하지 않습니다.

## 저장 구조

- Firebase Authentication: 아이디에 대응하는 내부 이메일과 비밀번호 인증. 비밀번호 해시는 앱 DB에 저장하지 않습니다.
- Firestore: people, accounts, members, contracts, sales, lessons, signatures, signature_payloads,
  salary_terms, rules, monthly_inputs, payroll_runs, payroll_versions, periods, source_records,
  review_decisions, audit 등 별도 컬렉션/문서.
- 손글씨 원본은 별도 signature_payloads 문서에 좌표 JSON 문자열로 저장합니다. 수업별 6000점 이하,
  개별 문서 800KB 이하이며 회원/날짜/회차 스냅샷·SHA-256과 연결합니다. Cloud Storage는 현재 사용하지 않습니다.
- 직원 계정은 관리자가 발급하며 실제 개인 이메일이 없어도 영문 아이디로 로그인할 수 있습니다.
  내부 인증 이메일은 사용자 아이디의 해시로 만들며 메일 수신용이 아닙니다. 비밀번호 복구는 관리자 초기화 방식입니다.
- 브라우저는 Firestore에 직접 접속하지 않습니다. 권한/정산은 서버에서 검사하고 보안 규칙은 직접 접근을 모두 거부합니다.
- Firebase 세션 쿠키 + 무작위 세션 식별자, HttpOnly/SameSite/Secure, CSRF 검사,
  직원/회원 모드 서버 잠금, 버전 충돌 검사, 중복 요청 키를 적용합니다.
- 정산 승인 당시의 계산·조건·경고를 별도 불변 스냅샷으로 보관합니다.
  서명·급여 스냅샷·감사 이력은 일반 앱 API로 덮어쓰거나 삭제하지 않습니다.
  프로젝트 소유자/서비스 계정은 별도 IAM 관리 대상입니다.

## 로컬 검증

Node.js 24 권장, Java 21 이상(Firestore 에뮬레이터), npm이 필요합니다.

    npm ci
    npm run test:firebase
    npm run test:firebase:browser
    npm test
    npm run check

Firebase 테스트는 demo-double-y 에뮬레이터만 사용합니다. 실서비스 Firebase나 결제 기능에 접속하지 않습니다.
기본 npm test는 기존 정산 회귀 검사이며 에뮬레이터가 없으면 Firebase 통합 검사는 건너뜁니다.
Firefox/Safari 등 모든 실기기를 검증한 것은 아닙니다. 브라우저 검증은 Chromium 모바일 터치 화면을 사용합니다.

로컬 화면을 직접 확인하려면 첫 터미널에서 다음을 실행합니다.

    npm run emulators

다른 터미널에서 .env.example을 .env.app.local로 복사하고 SETUP_TOKEN에 긴 임의 문자열을 설정한 후:

    npm start

http://127.0.0.1:3000 에 접속해 설정 코드로 최초 관리자를 만듭니다.
에뮬레이터 데이터는 종료 시 유지되지 않습니다. 실제 운영 저장소가 아닙니다.
Firebase Functions/Hosting 운영 배포 절차는 [FIREBASE.md](FIREBASE.md)를 따릅니다.

## 유지한 운영 기능

- 구성원별 직책·입사/종료일·적용 월별 기본급/시급·세율·매출 구간.
- 기존 회원 일괄 이관, 신규 회원 등록, 기존 회원 추가 결제와 각 회원권 단가/횟수 분리.
- 수업 날짜/시간과 회차를 구분하며 늦은 수업 입력/서명 수령 지원.
- 원본 서명 보존, 내용 변경 시 재서명 필요 표시.
- 다짐 텍스트 분석·중복 방지·변경 상태 명시 선택·회원별 집계·날짜순 대조·수동 연결.
- 미서명/다짐 불일치 경고, 직원 제출/관리자 반려·예외 사유 승인/전원 승인 후 마감·사유 있는 재개방.
- 매출·환불 원결제 연결·전액 환불 시 회원권 종료, 담당 인수인계 시 과거 매출/서명 유지.
- 일반 직원·알바는 본인 급여만, 트레이너는 본인 회원/수업/급여만, 관리자는 전체.
- 휴대폰 홈 화면 설치(PWA); 오프라인에서는 급여·서명 입력을 저장하지 않으며 온라인 재시도가 필요합니다.

일괄 회원 이관은 한 번에 40건, 다짐 원문은 한 번에 200건으로 나눕니다.
Firestore 트랜잭션 한도와 동시 수정 검증을 위한 범위입니다.
한 지점의 월별 업무를 전제로 하며 월 범위 조회는 12000건 상한에서 명시적으로 중단합니다.
앱은 최근 월/해당 회원권 기록을 조회하며 모든 연도 전체 자료를 매번 복사하지 않습니다.
거래 직렬화를 위해 control/state 문서를 사용합니다. 다지점/고빈도 확장 시 지점별 분할·집계 최적화가 필요합니다.

## 급여 기준

PT 수업료는 해당 수업 월의 신규+재등록 공급가액 매출로 비율을 결정한 뒤,
각 회원권의 공급가액 ÷ 등록횟수 × 해당 월 비율을 수업별 반올림해 합산합니다.
기본급·인센티브·추가수당 합계에 세율을 적용해 내림하고 별도 공제를 차감합니다.
계약별 사용횟수에는 이관 시 입력한 기진행횟수를 포함합니다.

| 직책 | 기본급 기본값 | 지급 기준 |
|---|---:|---|
| 오전파트 | 50만원 | 400만원 미만 35%, 400만원 이상 40%, 500만원 이상 50% |
| 일반 트레이너 | 100만원 | 0/400/600/800만원부터 30/40/45/50% |
| PT·필라테스 | 100만원 | 일반과 동일, 입사 첫 2개 역월 최소 45% |
| PT팀장 | 120만원 | 개인 45%, 600만원 이상 50%; 팀 PT 3000/3500/4000만원부터 전체 ×2/2.5/3% |
| 총괄매니저 | 300만원 | 개인 50%; 센터 8000만원까지 2%, 초과분 4% |
| FC팀장 | 250만원 | 회원권 3500/4000/4500만원부터 전체 ×2/2.5/3% |
| 직원/알바 | 관리자 입력 | 월급 또는 시급 × 입력 근무시간 |

일반/PT·필라테스는 월 매출 1000만원부터 20만원, 이후 200만원 증가마다 20만원을 추가합니다.
오전파트 지급률/기본급은 관리자가 적용 월별로 수정할 수 있습니다.
퇴사월 기본급은 자동 일할 계산하지 않으며 관리자가 월별 추가/공제에 반영합니다.
위 계산은 코드 검증 대상이며 실제 계약·세무 조건은 운영자가 확인해야 합니다.

## 백업과 이전

[FIREBASE.md](FIREBASE.md)의 관리형 예약 백업·PITR·Auth 별도 보관·복원 절차를 설정하세요.
휴대폰/PC를 끄거나 브라우저를 지워도 운영 Firestore 기록은 서버에 남습니다.
프로젝트 삭제/관리자 실수에 대한 백업까지 자동으로 갖춰진 것은 아닙니다.

    FIREBASE_PROJECT_ID=실제프로젝트 npm run firebase:export

관리자 자격 증명(ADC)을 사용해 문서별 JSONL+SHA-256을 로컬에 내보냅니다.
회원·계약·수업 고유 ID와 연결 정보가 보존되므로 다른 프로그램 이관에 활용할 수 있습니다.
Auth 비밀번호는 이 내보내기에 포함하지 않습니다. 별도 Auth 관리형 내보내기 또는 초기화가 필요합니다.
복원은 완전히 비어 있는 격리 Firestore에만 허용합니다. 운영 DB 덮어쓰기를 허용하지 않습니다.

이전 SQLite 구현은 회귀 검증/이관 참고용으로 남겼습니다. npm run start:sqlite로 별도 실행하며
Firebase와 자동 양방향 동기화하지 않습니다. [README-SQLITE.md](README-SQLITE.md)는 이전 저장 방식 문서입니다.
