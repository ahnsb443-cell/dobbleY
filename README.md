# DOUBLE Y · 언주역점 페이롤

회원·결제·수업·손글씨 서명·월별 급여·다짐 대조를 관리하는 서버형 웹앱입니다.
회원/회원권 고유 ID, 개별 SQL 테이블, 월 범위 조회와 페이지네이션, 원본 서명 분리 보관,
직원 제출·관리자 승인·월 마감, append-only 변경 이력, 일관 백업 및 격리 복원을 지원합니다.

**이 실행본은 단일 지점용 Node.js 24 + 영속 SQLite 서버입니다.**
PC 3대와 폰이 같은 서버에 접속합니다. 각 기기가 별도 DB를 복사하거나 Drive로 동기화하지 않습니다.
Firebase 연결/배포는 이 재구축 버전에 포함하지 않았습니다. SQLite 파일을 휘발성 서버리스
함수 파일시스템에 두면 안 됩니다. 외부 배포·환경 게시·GitHub push는 수행하지 않았습니다.

## 로컬 실행과 검증

필수 Node.js 24 이상. 런타임 외부 의존성은 없으며 npm 개발 의존성은 브라우저 검증용입니다.

    npm ci
    npm test
    npm run check
    npm start

기본 포트 3000, 개발 DB는 .data/payroll.sqlite입니다. 개발 모드에서 로컬 브라우저로 최초 관리자
이름·아이디·비밀번호를 설정합니다. 기본/공용 비밀번호는 없습니다.
외부 최초 설정은 SETUP_TOKEN이 필요하며 운영 모드는 HTTPS PUBLIC_ORIGIN과 Secure 쿠키를 요구합니다.
실제 비밀번호·토큰·DB·백업은 Git에서 제외합니다.

브라우저 검증은 시스템 Chromium 또는 Playwright 설치 브라우저를 사용합니다.
필요하면 npx playwright install chromium, 다른 경로는 CHROMIUM_PATH로 지정합니다.

    npm run test:browser
    npm run simulate

simulate는 임시 DB/가상 계정으로 10명 회원 이관 → 신규/추가 결제 → 실제 폰 터치 서명 →
누락 수업 보완 → 다짐 대조 → 직원 제출 → 관리자 승인 → 월 마감을 재현하고
reports/long-term-simulation에 화면과 자체 포함 HTML/PDF를 만듭니다. REPORT_DIR로 위치 변경 가능합니다.
운영 DB는 사용하지 않으며 가상 계정과 임시 DB는 종료 후 삭제합니다.

## 직원별 사용

- 관리자: 구성원·계정 발급, 월별 기본급/시급·세율·근무시간·수당·공제, 지급률 버전, 전체 매출·정산·다짐 검수.
- 트레이너 직원 계정: 본인 회원/계약·수업·서명·급여만 조회/입력. 기본급·지급률·공제 변경 금지.
- 일반 직원/알바 계정: 본인 급여·명세서 조회, 본인 비밀번호 변경.
- 임시 비밀번호는 첫 로그인 때 변경합니다. 계정 사용 중지·비밀번호 초기화는 기존 세션을 즉시 종료합니다.
- 계정 생성은 구성원 1명에 연결하며 같은 구성원에 중복 직원 계정을 만들지 않습니다.
- 수업 서명 화면 진입 시 **서버 세션 자체를 회원 확인 모드로 잠급니다.**
  다른 탭·새로고침에서도 해당 회원의 수업 확인 API만 허용합니다. 복귀에는 직원 비밀번호가 필요합니다.

## 회원·신규·추가 결제

기존 회원은 관리자 '회원 · 결제 → 기존 회원 일괄 등록'에서 엑셀 셀/UTF-8 CSV로 가져옵니다.
고유 회원번호와 등록번호를 사용하고 동명이인은 자동 병합하지 않습니다.
오류가 한 행이라도 있으면 저장을 막으며, 같은 등록번호 재입력은 중복에서 제외합니다.

열 순서:
회원번호 / 회원명 / 담당 / 등록번호 / 등록일 / 결제일 / 공급가액 / 등록횟수 / 기진행횟수 / 기준일

기진행 기준일은 앱에 날짜별 기록을 시작하는 기준입니다. 그 이전의 소진은 기진행횟수에 포함하며
별도 수업으로 중복 입력하지 않습니다. 이미 마감된 월의 과거 결제를 뒤늦게 가져오려면 먼저 검토가 필요합니다.
담당은 고유한 구성원 표시 이름과 일치해야 하며 동명 담당은 오류로 표시합니다.

신규 회원은 이름과 계약을 한 트랜잭션으로 생성합니다.
추가 결제는 기존 회원 카드를 선택해 계약만 추가합니다.
서로 다른 계약의 단가·잔여는 합치지 않습니다. 수업마다 사용 계약을 명시적으로 선택합니다.

## 급여 계산

모든 매출 기준은 VAT 제외 공급가액. VAT 포함 입력은 ÷1.1 후 원 단위 반올림합니다.
월 1일~말일 결제와 환불을 기준으로 매출을 계산하고 카드수수료를 차감하지 않습니다.
수업료 = 원계약 공급가액 ÷ 등록횟수 × 수업 월 지급률, 회당 원 단위 반올림 후 합산.

| 직책          | 기본 보수 기본값 | 조건                                                                                    |
| ------------- | ---------------- | --------------------------------------------------------------------------------------- |
| 오전파트      | 50만원           | 400만원 미만 35%, 이상 40%, 500만원 이상 50%                                            |
| 일반 트레이너 | 100만원          | 400/600/800만원부터 40/45/50%, 미만 30%. 1,000만원부터 20만원, 이후 200만원마다 +20만원 |
| PT·필라테스   | 100만원          | 개인 합산 일반 구간. 입사 월 포함 두 달 최저45%                                         |
| PT팀장        | 120만원          | 본인 매출 600만원 미만45%, 이상50%. PT팀 3,000/3,500/4,000만원부터 전체 ×2/2.5/3%       |
| 총괄매니저    | 300만원          | 개인레슨50%, 센터8,000만원까지2%, 초과분만4%                                            |
| FC팀장        | 250만원          | 회원권3,500/4,000/4,500만원부터 전체 ×2/2.5/3%                                          |
| 직원/알바     | 입력             | 기본급 또는 시급 × 해당 월 근무시간                                                     |

직책·기본급·시급·세율은 적용 시작 월을 가진 버전입니다. 근무시간·수당·공제는 해당 월만 적용합니다.
기준 변경은 제출/마감 월에 소급 적용하지 못하며, 이미 승인된 정산은 저장된 계산 근거를 조회합니다.
프리랜서 기본 세율3.3%는 원 미만 절사한 예상 합산 원천징수입니다.
별도 세금 신고/소득세·지방소득세 분리 계산·4대보험·주휴/연장수당·계약종료 정산금은 지원하지 않습니다.
실제 지급 전 담당자의 검토가 필요합니다.

## 서명·정정·미서명

'수업 완료 · 회원 서명'에서 날짜·시간과 계약을 선택합니다.
일자와 회차를 별개로 보여주고 회원이 실제 터치 획과 수업 확인 체크를 저장합니다.
서명은 별도 payload 테이블에 보관하며 일반 수업/급여 응답에 획을 포함하지 않습니다.
날짜·시간·회차·회원권 내용이 달라지면 재서명으로 표시하고 이전 원본은 보존합니다.
이후 날짜의 수업만 추가하는 것은 이전 서명을 무효화하지 않습니다.
기존 수업의 누락 서명은 나중에 받을 수 있고 실제 저장 시각을 남깁니다. 미래 완료 수업은 금지합니다.

서명된 수업을 취소하려면 관리자 권한과 사유가 필요합니다. 물리 삭제하지 않고 취소 이력을 보관합니다.
직원의 중복 클릭/네트워크 재시도는 요청 키로 중복 저장을 막고, 같은 계약·날짜·시간의 중복 수업도 차단합니다.
서로 다른 시간의 같은 날 수업은 별개로 기록할 수 있습니다.

손글씨 수업 확인 기록이며 회원 휴대폰 본인 인증·공인 인증서 서명·외부 공인 타임스탬프는 아닙니다.
법적 효력이 종이와 자동 동일하다고 보장하지 않습니다. 회원 안내/보관 기간/기기 인계 절차를 정해야 합니다.

## 다짐 대조와 정산 마감

다짐 목록을 붙여넣어 날짜·시간·강사·회원·상태·회원권만 추출합니다.
연락처와 원본 텍스트는 보관하지 않습니다. 예약완료 아래 예약취소는 버튼으로 해석합니다.
중복은 제외하고 기존 상태 변경은 관리자가 명시 선택해야 합니다.
직원에게 전체 다짐 원장을 반환하지 않습니다.

강사·회원명이 고유하게 일치할 때 연결하되, 동명이인·여러 계약/예약은 수동 연결과 검수가 필요합니다.
회원별 출석 집계, 원장 연결, 날짜/시간 대조와 검수 사유를 제공합니다.
다짐 출입 출석은 실제 PT 완료·서명·지급 승인과 동일하지 않습니다.
전체 페이지를 빠짐없이 가져왔는지는 관리자가 확인해야 합니다.

작성 중 → 직원 제출 → 관리자 승인 → 전체 월 마감.
제출/승인 후 금융 자료 수정은 관리자 반려가 필요합니다.
승인 전에 미서명·다짐 미가져오기·미해결 대조가 있으면 관리자 예외 사유가 필수입니다.
불일치 검수도 대상의 버전/내용을 기록하므로 내용이 바뀌면 이전 확인을 재사용하지 않습니다.
늦게 받은 서명이나 추가 증빙은 기록할 수 있지만 확정 금액을 자동 변경하지 않습니다.
서명 확인 현황은 현재 상태와, 승인 시 보관한 과거 경고를 구분합니다.

모든 대상 직원 승인 후 월을 마감하며 명세·거래·수업·기준 버전을 고정합니다.
수정이 필요하면 관리자 사유로 마감을 해제하고 재제출/재승인합니다. 이전 확정본은 삭제하지 않습니다.
급여 승인/마감과 실제 은행 송금은 별개입니다. 앱이 자동 송금하지 않습니다.

## 운영과 보관

OPERATIONS.md의 HTTPS·서버·백업·복원·업그레이드 절차를 따르세요.
초기 배포·인증서·외부 주소·스케줄러 설치는 아직 실행하지 않았습니다.
한 지점의 다중 기기를 위한 구조이며 여러 지점을 하나의 DB로 분리 운영하는 기능은 없습니다.
공용 DB 파일은 영속 디스크에 보관하고 코드 갱신 폴더와 분리하는 것이 좋습니다.
소스는 Git 커밋과 소스 ZIP으로 보관하되 DB·서명·비밀 값은 Git에 넣지 않습니다.

## 계약 종료와 담당 인수인계

관리자가 구성원 관리에서 마지막 근무일을 기록하면 다음 날부터 로그인이 차단되고 이후 월 정산에서 제외합니다.
마지막 근무 월은 정산 대상이며 기본급 일할 계산은 자동이 아니므로 월별 별도 공제로 실제 조건을 반영해야 합니다.
새로운 담당에게 회원을 인수인계할 때는 회원권의 잔여를 유지하고 기존 결제·수업·서명은 기존 담당의 기록으로 남깁니다.
인수인계는 현재 또는 과거 적용일의 사유 있는 관리자 작업이며 앞으로 진행하는 수업은 새 담당에게 기록합니다.
이미 기록한 수업의 담당과 과거 매출을 인수인계일 기준으로 자동 소급 재배분하지 않습니다.
종료 후 재입사나 서로 다른 지점 간 직원 이동은 별도 계약/운영 검토가 필요합니다.
