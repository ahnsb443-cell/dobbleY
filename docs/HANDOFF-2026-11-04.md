작성일: 2026-11-04. 이 문서는 다른 채팅/새 작업환경에서 개발을 이어가기 위한 기준 문서다.
운영 개인정보 전체를 내보낸 자료가 아니며, 아래 회원 조정 내용은 이전 작업에서 확인한 이력이다. 현재 잔여를 재확인한 운영 DB 스냅샷으로 오해하지 말 것.

## 2. 제품 범위와 확정 결정

- 주 기능은 PT 수업 체크·회원 서명·잔여 관리·급여 정산이다. 회원권 CRM 전체를 다시 만들지 않는다. 다짐 CRM을 병행한다.
- 예약은 다짐에 입력하고 수업 사인지는 이 웹앱에서 받는다. 다짐과 실시간 양방향 자동 동기화하지 않는다. 기존 가져오기·대조 기능을 사용한다.
- 신규/추가 등록은 결제가 끝난 상품만 저장한다. 선생님도 본인 담당 회원의 신규 등록과 같은 회원 안의 추가 상품을 입력할 수 있다.
- 추가 상품은 기존 상품을 덮어쓰지 않고 별도 계약/서명지로 만든다. 수업 때 차감할 상품을 선택한다.
- 총 결제와 매출 입력은 통상 VAT 포함, 정산 기준 매출·회당 공급단가는 VAT 제외다. 이미 공급가로 승인한 상품을 다시 1.1로 나누지 않는다.
- 회당 고정 수업료 20,000원은 올바른 약정이다. 비율제 단가 20,000원으로 바꾸거나 강사 지급률을 다시 곱하지 않는다.
- 대표는 급여가 없지만 관리자와 동일한 조회·등록·수정·삭제 권한을 가진다.
- 총괄매니저도 본인 수업을 기록한다. 관리자 홈의 수업 체크에서 강사 선택이 가능하다.
- 임시 서명 화면에 진입하거나 서명을 그린 것만으로 저장하지 않는다. 저장 없이 돌아오면 새 수업·잔여·급여에 영향이 없다.
- 저장 성공 후 1.5초간 완료 안내를 표시하고 홈으로 돌아간다. 복귀 비밀번호를 재요구하지 않는다.
- 노쇼는 회원 서명 없이 1회 차감·정상 수업료 반영. 미서명과 구분하고 다짐 출석 대조에서 제외한다.
- 그룹 수업은 참여 0명일 때 하프 페이, 1명 이상은 약정 수업료다. 타 강사의 단가를 선생님에게 노출하지 않는다.
- 기존 원본 서명·급여 확정 스냅샷·감사 이력은 일반 수정/삭제로 파괴하지 않는다.

## 3. 현재 구현 기능

### 회원·상품·수업

회원 검색, 선생님별 담당 제한, 신규 결제, 재등록 상품, 상품별 서명 목록, 기초잔여 이관·정정, 담당 인수인계, 수업 정정·취소가 있다. 개인·듀엣·그룹·시급/일급 근무를 지원한다.
관리자 수업 삭제는 논리 취소로 처리한다. 활성 차감과 정산에서 제외하고 잔여를 복구하되 원본 서명·삭제 사유는 보존한다. 듀엣은 두 회원을 함께 처리한다. 정산 제출/승인/마감 이후 변경에는 반려/마감 해제가 필요하다.

### 이번에 배포한 회원 서명 개선 (`e56fe90`)

- 상단: 선택한 이용권의 전체/현재 사용/현재 잔여. 남은 횟수를 가장 크게 표시한다.
- 최근 수업 날짜는 선택한 이용권의 현재 확인 건을 제외한 활성 수업 중 최신 날짜다. 기록이 없으면 없다고 표시하며 이관분의 날짜를 만들어내지 않는다.
- 중간: 회원명, 실제 선택한 수업일·시간, 담당, 이번 회차, 이번 차감 1회, 확인 완료 후 잔여.
- 새 수업은 차감 전 현재 잔여와 저장 후 잔여를 구분한다. 이미 기록된 수업에 누락 서명/재서명을 받는 경우 추가 차감 0회임을 명시한다.
- 이전 기록은 현재 서버 세션의 회원만 조회한다. 다른 상품의 기록도 같은 회원이면 포함한다. 최근 날짜/시간순, 10건씩 더 보기.
- 현재 확인 중인 기존 수업 자체는 이전 수업 목록에서 제외한다. 해당 수업의 과거 원본 전체가 필요하면 관리자 수업별 서명 이력 기능을 사용한다.
- 각 수업의 차감 여부와 signed/unsigned/stale/noshow/void 상태, 저장된 서명별 원본 확인 기능을 제공한다. 서명 이미지가 없으면 정확히 표시한다.
- 과거 서명에 기록된 회차 후 잔여는 당시 저장한 원본 값이다. 현재 전체 잔여로 취급하지 않는다.
- 기록 패널은 작성 화면을 교체하지 않고 숨긴다. 손글씨·확인 체크·노쇼 선택·재시도 요청 키를 유지한다. 패널 복귀 버튼과 브라우저 뒤로가기를 지원한다.
- 서명과 원본 캔버스는 불투명 흰 배경·검정 획을 유지한다.
- 기록 조회 중에는 앱 본문이 숨겨지고 서버의 회원 모드 제한도 유지된다.

주의: 기존 요구대로 비밀번호 없는 홈 복귀와 저장 후 자동 홈 복귀를 유지한다. 복귀 이후는 다시 선생님/관리자 화면이다. 회원에게 건넨 상태를 생체 인증 등으로 계속 식별하는 별도 잠금 기능은 없다. 향후 공용 태블릿 전환 시 명시적인 선생님 복귀 잠금 정책을 다시 결정할 것.

### 페이롤과 권한

선생님 모바일 홈, 개인 페이롤, 당월 회원별 서명 확인, 관리자 전체 정산·다짐 대조·월말 제출/승인/마감이 있다. 당월 서명 목록은 모든 페이지를 읽어 회원별로 묶는다. 승인 명세는 당시 계산 결과를 보존하고 현재 서명 상태와 구분한다.
직원은 본인 자료, 관리자/대표는 전체 자료를 관리한다. 그룹 강사는 서버에서도 본인 단가만 조회하며 미연결 직원의 전체 단가 조회를 막는다.

## 4. 정산 약정

모든 구간은 별도 명시가 없으면 월 공급가액 기준. 기본 직책 구간은 `lib/profiles.mjs`, 월별 조건과 실제 계산은 `firebase/domain.mjs`, `firebase/workflow.mjs`, `firebase/classes.mjs`를 함께 확인한다. 월별 `salary_terms`가 기본값보다 우선할 수 있다.

| 대상                | 확정 기준                                                                                                                                                                                                |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 문승훈              | 2026-11까지 최소 수업료율 40%. 높은 매출 구간 요율이면 높은 값 적용. 보장 종료 월은 2026-11. 회당 고정 수업료에는 이 비율을 곱하지 않음.                                                                 |
| PT 공통 개인 성과금 | 오전/일반/겸용/PT팀장 모두 개인 월 공급 매출 1,000만원부터 20만원, 이후 200만원마다 +20만원. FC/총괄/그룹에는 공통 성과금 자동 추가하지 않음.                                                            |
| FC팀장              | 센터 멤버십 공급 매출 3,500만/4,000만/4,500만원 이상에 2%/2.5%/3%. 달성 요율을 전체 기준 매출에 적용.                                                                                                    |
| 총괄매니저          | 센터 전체 매출(FC+PT 등) 8,000만원까지 2%, 초과분만 4%. 본인 개인 수업료 기본 50%.                                                                                                                       |
| PT팀장              | 본인 포함 PT팀 공급 매출 3,000만/3,500만/4,000만원 이상에 2%/2.5%/3%. 총괄매니저 개인 PT·개인/그룹 필라테스 제외. 본인 개인 지급률은 개인 매출 600만원 미만 45%, 이상 50%. 개인 공통 성과금과 별도 합산. |
| 그룹                | 약정 시간당 단가 × 인정시간. 참여 0명이면 절반. 저장 당시 단가를 보존.                                                                                                                                   |
| 대표                | 본인 급여·급여 입력을 생성하지 않음. 관리자 권한은 부여.                                                                                                                                                 |

센터 멤버십 월 순매출 합계를 입력하면 개별 멤버십 원장과 중복 합산하지 않는다. 총괄매니저 판매 PT는 센터 전체에는 포함하지만 PT팀 집계에서는 제외한다. 이미 마감된 과거 정산을 새 정책으로 소급 재계산하지 않는다.

## 5. 회원 데이터 이관·정정 이력

아래는 사용자가 승인하고 이전 작업에서 반영한 기준이다. 운영 DB에 이후 수업이 추가됐을 수 있으므로 이 숫자로 현재 값을 강제 덮어쓰지 말 것. 회원 연락처·생년월일·전체 명단은 문서/ZIP에 싣지 않았다.

- 기준 원본: `더블와이짐 언주역점_회원_엑셀_2026_11_02.xlsx`, 잔여는 11월 2일 기준. PT만 대조하며 회원권·필라테스는 이번 PT 대조에서 제외. Y2는 PT다.
- 이름: 루스만 조냐, 남요완이 맞다. 유병애와 유병아는 같은 회원이며 유병아로 수정했다.
- 우재원 담당 한금주: 총 24회, 10월 4회 + 실제 11월 서명 1회를 기준으로 당시 잔여 19회. 이관 차감과 실제 수업을 중복 차감하지 않도록 정정했다.
- 우재원 담당 박소연: 총 20회, 이관 사용 1회, 당시 잔여 19회.
- 우재원 담당 권경난: 총 10회, 이관 사용 5회, 당시 잔여 5회.
- 우재원 담당 신재경: 기존 44회 중 이관 사용 42회, 잔여 2회는 강사 고정 수업료 20,000원. 과거 상품에 11월 신규 매출을 만들지 않았다.
- 신재경 추가 상품: 2026-11-02, 50회/3,000,000원, 대표 승인 공급가 기준. VAT를 다시 제외하지 않으며 회당 공급단가 60,000원에 강사 지급률을 적용. 기존 2회 상품과 별개 상품/매출로 저장했다.
- 권채운: 결제 완료 후 홀드 요청을 거쳐 최종 이건우 배정. 인수 전 프로모션 10회, 공급가 매출 220,000원, 강사 고정 수업료 20,000원. 11월 매출로 반영했다. 이 상품도 다시 VAT 제외하지 않는다.
- 과거 한금주 회차 정정으로 원본 대비 재확인이 필요한 서명이 생긴 이력이 있다. 원본을 덮어쓰지 않았다.
- 신연재(원본 12회 vs 앱 38회), 이태훈(원본 36회 vs 앱 30회) 등은 추가 확인 없이 임의 정정하지 않았다. 현재 운영 상태부터 재확인할 것.
- 전체 수업 체크 취소와 일부 서명대기 취소 요청은 과거에 처리됐다. 이 요청들을 새 채팅에서 다시 실행하지 않는다.

금액 없는 누락 회원을 추측 단가로 등록하지 않는다. 잔여 정정은 `firebase/balances.mjs`의 `reconcileOpeningBalance` 등을 사용하고, 실제 활성 수업을 뺀 기초 사용분만 조정한다. 원본 스프레드시트의 현재 잔여를 `carry_used`에 그대로 넣지 않는다.
소스 ZIP에는 원본 PDF·엑셀 및 운영 DB가 없다. 별도 비공개 재개 패키지를 받은 경우 private-reference의 원본과 과거 제한된 대조 자료를 참고할 수 있다. 그 자료도 현재 운영 DB 전체 백업은 아니다.

## 7. Firestore 데이터 구조

문서 키는 기본 UUID 계열 문자열. 월별 구성원 자료는 `personId_month` 형식을 사용한다. 정확한 전체 필드는 각 생성 함수를 확인한다.

| 컬렉션                                                 | 주요 내용/관계                                                                                                                                                                |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `people`                                               | 구성원 id/name/profile/hire_month/end_date/active/version.                                                                                                                    |
| `accounts`                                             | Auth UID와 앱 role/person_id/active/must_change/version/PIN 관련 정보. 비밀번호 원문은 없음.                                                                                  |
| `salary_terms`, `rules`                                | 적용 월별 기본급·세율·직책·보장 요율 등 / 정산 규칙.                                                                                                                          |
| `members`                                              | 회원 id/name/person_id/external_ref/active/version.                                                                                                                           |
| `member_assignments`                                   | 회원 담당자 변경 이력. 과거 수업/매출 소유권을 덮어쓰지 않음.                                                                                                                 |
| `contracts`                                            | 회원의 상품. member_id/person_id/category/quantity/carry_used/start_date/carry_date/paid_date/amount/gross_amount/amount_basis/fixed_fee/payment_confirmed/active/version 등. |
| `sales`                                                | 상품/회원/구성원과 연결한 결제·환불, month/category/kind/amount, 팀 매출 포함 여부 등.                                                                                        |
| `lessons`                                              | contract_id/member_id/person_id/date/time/month/status/version/latest_signature_id/session_id/format/no_show. `status=active`만 차감 대상.                                    |
| `signatures`                                           | lesson_id/person_id/snapshot/fingerprint/signed_at/actor_id/payload_hash/confirmation. 새 서명마다 별도 원본 생성.                                                            |
| `signature_payloads`                                   | 서명 id와 동일 키, `strokes`에 정규화 좌표 배열을 JSON 문자열로 저장. PNG 파일이 원본인 구조가 아님.                                                                          |
| `group_rates`, `group_lessons`                         | 강사별 단가/인정시간 및 수업 당시 확정 단가·인원·지급액.                                                                                                                      |
| `duet_sessions`                                        | 두 회원 수업의 공통 세션, 원자 정정/취소 연결.                                                                                                                                |
| `monthly_inputs`, `membership_totals`                  | 구성원별 월 추가 입력 / 센터 월 멤버십 순매출 합계.                                                                                                                           |
| `payroll_runs`, `payroll_versions`, `periods`          | 정산 상태·승인 당시 불변 명세·월 마감 상태.                                                                                                                                   |
| `source_records`, `source_batches`, `review_decisions` | 외부 출석 원본·가져오기·대조 결정 등. 실제 컬렉션 명은 imports 코드도 확인.                                                                                                   |
| `auth_sessions`                                        | 세션 해시, account_id, version, expires, csrf, member_lesson_id 또는 member_draft.                                                                                            |
| `idempotency`, `unique_keys`                           | 재전송 응답과 내용 해시 / 중복 수업 슬롯·외부번호 방지.                                                                                                                       |
| `audit`, `control`, `attempts`                         | 변경 감사 이력 / 전역 변경 revision / 로그인 시도 제한 등.                                                                                                                    |

잔여 공식: `used = carry_used + 해당 contract의 active lessons 건수`, `remaining = quantity - used`.
이미 저장된 수업의 서명 저장은 `lessons`를 새로 추가하지 않는다. 듀엣은 회원별 lesson 1건씩 차감한다. 노쇼도 활성 lesson 1건이다. 서명 이미지가 없다는 이유로 수업 차감 자체를 다시 실행하지 않는다.

서명 snapshot 필드: lessonId/contractId/memberId/personId/member/instructor/date/time/ordinal/registered/remaining/category. `remaining`은 해당 순번 이후 값이며 현재 상품 전체 잔여와 항상 같지는 않다. 최신 UI는 별도 `balance`로 현재 값을 표시한다.

Firestore 보안 규칙은 브라우저 직접 접근을 거부한다. 브라우저 → 같은 출처 API → 앱 권한 확인 → Admin SDK 순서다. Cloud Storage는 현재 서명 저장소로 쓰지 않는다.

## 8. 회원 모드와 중복 방지

`POST /api/member-mode`에 contractId/date/time을 보내면 서버 세션에 `member_draft`를 만든다. 버퍼 미반영 미리보기로 검증하므로 이 단계에서는 수업 원장/차감/급여가 없다.
기존 lessonId로 들어가는 흐름은 해당 활성 수업을 선택한다.

- `GET /api/member-mode`: snapshot, version, confirmation, 현재 balance, 유효한 저장 서명 획 등.
- balance: quantity/used/remaining/deduction/additionalDeduction/afterRemaining/recentDate. 새 draft의 additionalDeduction=1, 기존 lesson=0.
- `POST /api/member-mode/sign`: version/snapshot/confirmed/strokes, 필요 시 noShow, 새 화면에서는 balance도 전송.
- draft는 수업 생성과 서명 저장을 한 트랜잭션에서 수행. 오류면 둘 다 취소.
- 저장 직전에 balance와 snapshot을 재검사. 화면을 연 뒤 잔여/회차가 달라지면 HTTP 409로 재확인을 요구.
- `Idempotency-Key`는 같은 화면의 재시도 동안 유지. 서버는 같은 키/내용에 이전 응답을 돌려주며 다른 내용 재사용은 거부.
- `GET /api/member-mode/history?after=...`: 세션 회원의 이전 수업 10건. 요청에 임의 memberId를 붙여도 대상 변경 불가.
- `GET /api/member-mode/history-signature?id=...`: 원본 수업의 member_id가 세션 회원과 일치할 때만 획 반환. payload 누락은 strokes=null.
- `POST /api/member-mode/exit`: draft 해제, 기존 기록은 유지. 비밀번호 재입력 없음.

회원 모드에서 일반 회원·급여·관리 API를 호출하면 403. 같은 기기 세션의 다른 탭도 제한한다. 전체 계정의 다른 기기까지 잠그는 구조는 아니다.
쓰기 요청은 CSRF·버전·월 마감 상태·권한 검사를 거친다. 불변 서명·급여 버전·감사 자료는 일반 API로 삭제하지 않는다.

## 9. 새 환경 복원과 검증

권장 로컬 Node.js 24, 최소 package.json의 Node 요구사항 충족, Java 21+, npm, Chromium 또는 Playwright Chromium.

```bash
git clone --branch firebase-release-v2 https://github.com/ahnsb443-cell/dobbleY.git
cd dobbleY
npm ci
npm run check
npm test
npm run test:firebase
npm run test:firebase:browser
```

ZIP을 사용하면 Git clone 대신 압축을 풀고 해당 디렉터리에서 실행한다. ZIP에는 `.git`이 없으므로 원격 최신 작업/계속 커밋이 필요하면 Git clone을 권장한다.
Chromium이 없으면 `npx playwright install chromium`으로 설치한다. 환경별 네트워크·로컬 포트 권한이 필요할 수 있다.

이번 기능 집중 검증:

```bash
npx firebase emulators:exec --only auth,firestore --project demo-double-y 'node --test --test-isolation=none test/firebase.test.mjs test/classes.firebase.test.mjs'
npx firebase emulators:exec --only auth,firestore --project demo-double-y 'node scripts/browser.mjs --firebase --manager-record --dark-signatures'
```

위 두 명령은 별도 에뮬레이터 실행으로 나누어야 한다. API 검사가 만든 관리자 계정이 남아 있으면 브라우저 검사의 최초 설정 화면이 나오지 않아 실패한다. 에뮬레이터를 새로 띄우고 재검사할 것.
수동 개발은 첫 터미널 `npm run emulators`, 새 환경에서만 `.env.example`을 `.env.app.local`로 복사해 SETUP_TOKEN을 로컬 임의값으로 설정한 후 두 번째 터미널 `npm run start:firebase`. 실제 설정 파일을 덮어쓰지 않는다.

2026-11-04 기능 배포 전 결과: 문법 검사 41파일 통과, 기본 검사 27통과/12건 에뮬레이터 미실행으로 건너뜀/실패0, 별도 Firebase 통합 36/36 통과. Chromium에서 320px/390px 가로 넘침 없음, 원본 서명 표시, 기록 조회 전후 캔버스/확인 체크 동일, 브라우저 뒤로가기 보존, 미저장 무반영, 다크/고대비 가독성 확인.
실제 모든 Galaxy/iPhone 모델의 현장 검증을 완료한 것은 아니다. 캡처는 실제 UI + 격리된 가상 데이터다. [잔여·서명·기록 화면 캡처](screens/member-signature/README.md)를 함께 제공한다.

## 10. 운영 배포·인증·백업

```bash

```

규칙/인덱스 변경 시 별도 검토·배포가 필요하다. 이번 잔여/기록 기능에는 인덱스·규칙 변경이 없었다.
`pinTag` 때문에 Hosting만 지정해도 연결 함수가 함께 배포될 수 있다.
새 환경에서는 소유자가 정상 Firebase CLI 로그인/권한 설정을 해야 한다. 과거 채팅의 일회성 인증 코드를 재사용하지 않는다. 운영 비밀값은 Secret Manager의 `SETUP_TOKEN`, 비밀이 아닌 배포 설정은 루트 `.env.dobbley-gym-payroll` 형식이며 ZIP에는 템플릿만 있다. 서비스 계정 키·로그인 쿠키·PIN을 소스에 넣지 않는다.

기존 서비스에 새 최초 관리자 설정을 실행하거나 demo 자료를 올리지 않는다. DB/계정을 새로 만드는 것이 복원이 아니다.

## 11. 남은 작업과 한계

1. 선생님 PDF/HTML 가이드에 이번 잔여/이전 서명 패널 설명과 캡처를 추가하면 좋다. 기존 가이드는 배포돼 있지만 이번 UI 변경분은 아직 미반영.
2. Galaxy Chrome/삼성 인터넷·iPhone Safari/PWA에서 현장 확인: 터치 서명, 다크모드, 기록 이미지, 화면 회전, 저장 중 통신 단절·재시도.
3. 회원에게 폰을 건넨 동안 저장 후 자동 복귀까지 가리는 추가 정책을 원한다면, 기존 ‘비밀번호 없는 즉시 홈 복귀’ 요구와 함께 새 정책을 결정해야 한다. 현재는 회원 모드 동안만 제한한다.
4. 이전 기록은 서버에서 회원 수업을 읽고 정렬해 10건을 제공한다. Store 조회 상한 12,000건을 넘으면 오류로 중단하며 조용히 잘라내지 않는다. 장기 대량화 시 인덱스 기반 서버 페이지네이션을 검토.
5. 이관분에 실제 서명/날짜가 없으면 기록을 만들어내지 않는다. 원본 계약서/엑셀과 추후 대조할 사항은 확인 후 제한된 범위로 처리.
6. 운영 백업/PITR·복원 훈련·모니터링은 실제 설정을 재확인해야 한다.
7. SQLite 경로는 보존돼 있지만 새 회원 balance/history API는 Firebase 경로에 구현했다. 운영은 Firebase다.

## 12. 운동 기록 앱 통합 논의 — 아직 미구현

참고 앱은 지인의 https://healthdi-log.web.app/ 이다. 이 저장소의 소스가 아니며 코드/DB 접근 권한을 확보한 상태도 아니다.
TinyFish에 저장한 Google 세션으로 로그인 버튼→기존 계정 선택을 진행해 내부 홈/운동 화면에 접속했고, 메뉴 홈·운동·식단·분석·코치, 달력/운동 이력을 확인했다. 계정/쿠키는 ZIP이나 다음 채팅으로 전달하지 않는다.

사용자 설명과 실제 제공 스크린샷으로 확인한 라이브 흐름: 종목·무게·반복수·목표 세트/휴식 설정 → 세트 시작 → 종료 → 휴식 타이머 → 자동 다음 세트. 휴식 중 다음 무게/횟수 조정, 지금 시작/+30초, 세트 목록, 보조 반복, 잠금 화면이 있다. 모든 입력/저장 동작을 브라우저로 끝까지 시험한 것은 아니다.

방향만 논의했다:

- 회원용 개인운동과 선생님용 PT 기록 구분, 회원 DB에 수업 피드백 연동.
- 공용 태블릿은 회원 선택·지난 수업 불러오기·바뀐 무게/횟수만 수정·세트 완료 중심으로 최대한 간단하게.
- 코칭 중에는 타이머를 필수 조작으로 강제하지 않는 방안 검토.
- 개인운동은 잔여/급여에 영향 없음. PT 운동 세트와 PT 수업 차감을 분리하고 최종 수업 확인/서명에서 1회만 처리.

아직 별도 회원 앱/회원 로그인, 운동 종목·세트 DB, 타 앱 자동 동기화, 선생님 피드백 저장 연동을 구현하지 않았다. 사용자 승인 없이 타 앱 코드를 복제하거나 기존 페이롤 DB를 새 구조로 초기화하지 않는다.

## 14. 인증·비공개 참고자료 전달 범위

소스 ZIP은 공개 저장소에 올릴 수 있는 코드/문서/가상 캡처만 포함한다. 사용자가 요청한 확장 재개 ZIP은 소스 외에 현재 환경의 관련 원본 계약 PDF·회원 XLSX·과거 한정 대조 스크립트/JSON·공개 Firebase 연결 설정을 별도 private-reference/runtime-config에 포함한다. 확장 ZIP은 실제 회원 개인정보가 있으므로 공개 Git/Hosting에 올리지 않는다.

WEB_API_KEY와 PUBLIC_ORIGIN은 Firebase 연결 설정이며 관리자 로그인 권한 자체가 아니다. 확장 패키지에서도 허용된 공개 설정 키만 제공한다. Firebase CLI OAuth/refresh token, Google/TinyFish 쿠키, 계정 PIN/비밀번호, 서비스 계정 비밀키, Secret Manager 값은 포함하지 않는다. 기존 운영 SETUP_TOKEN은 서버에 연결돼 있으므로 정상 권한의 배포가 이를 계속 참조한다. 새 환경에서 이를 새로 덮어쓰거나 최초 설정을 다시 하지 않는다.

같은 작업환경을 다른 채팅에서 다시 연결할 수 있다면 그 환경의 기존 CLI 인증을 정상 사용해 재인증 없이 이어갈 수 있다. 새 환경이면 소유자 Firebase 권한을 정상 연결해야 하며 ZIP 자체는 인증을 부여하지 않는다. 이 차이를 사용자에게 명확히 알릴 것.
